# Two-step RAG Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a Python CLI that indexes local documents into PGVector and answers questions using Google models with original-source references.

**Architecture:** Keep application code in `main.py`, with focused functions and a small storage adapter. Use LangChain documents, splitters, Google integrations, and PGVectorStore retrieval; LangGraph runs retrieve then generate. Precompute file embeddings before atomically replacing rows in the table used by PGVectorStore.

**Tech Stack:** uv, Python (existing project floor: >=3.14), LangChain, LangGraph, langchain-google-genai, langchain-postgres, SQLAlchemy, psycopg3, pypdf, python-dotenv, pytest, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-10-11-rag-poc-design.md`

## Global Constraints

- A single Python script with separate indexing and retrieval functions.
- Google Gemini API with a `GOOGLE_API_KEY`; documents are local files; questions are independent rather than conversational.
- Supported input formats are plain text, Markdown, and PDFs with extractable text.
- There is one retrieval step and at most one chat-model generation call per question.
- The database replacement is atomic per source: persistence failures preserve the previous version.
- Reference labels and locations are rendered from stored metadata, never invented by the model.
- No automatic removal of files absent from a directory scan; no OCR, UI, chat memory, or agent retrieval loops.

## Review Focus

- Repeated text and CRLF input must retain accurate original line ranges (Task 1).
- A shorter replacement and an insertion failure must not expose stale chunks or erase the previous version (Task 2).
- An existing index with a different embedding model or dimension must fail before Google calls (Task 2).
- Gemini blocked, empty, or non-string output must not produce an apparently successful answer (Task 3).
- Mixed directories with a corrupt PDF must retain successful files and return a failing exit status (Task 4).

## File Map

- Modify `main.py`: all application functions and CLI.
- Modify `pyproject.toml`; create `uv.lock`: runtime and test dependencies.
- Create `compose.yaml`, `.env.example`; modify `.gitignore`: local database and configuration.
- Create `tests/test_documents.py`, `tests/test_storage.py`, `tests/test_rag.py`, `tests/test_cli.py`: isolated behavior checks; storage checks use a dedicated PostgreSQL test database.
- Modify `README.md`: runnable instructions and limitations.

## Concrete Defaults and Integration Decisions

- Variables: `GOOGLE_API_KEY`, `GOOGLE_CHAT_MODEL`, `GOOGLE_EMBEDDING_MODEL`, `EMBEDDING_DIMENSION`, `DATABASE_URL`, `CHUNK_SIZE`, `CHUNK_OVERLAP`, `RETRIEVAL_K`.
- Defaults: chat `gemini-3.7-flash`, embeddings `gemini-embedding-2-preview`, dimension 768, chunk size 1000 characters, overlap 200 characters, retrieval count 4. These model IDs are current LangChain documentation examples; the embedding model is explicitly a preview. Both IDs can be overridden without editing code; changing embeddings requires a new index.
- Google clients explicitly use Gemini API rather than automatic Vertex AI selection. Pass output dimensionality explicitly; follow the selected embedding model's documented query/document task settings. Use a 60-second request timeout and at most two retries, mapped to the integration's supported parameter names.
- Compose uses `pgvector/pgvector:pg16`, host binding `127.0.0.1:6024:5432`, database/user `rag`, local development password `rag`, named volume `rag_pgdata`, and a `pg_isready` health check. Default application URL: `postgresql+psycopg://rag:rag@localhost:6024/rag`.
- Use fixed tables `rag_chunks` and `rag_index_config`. Chunk columns: UUID `langchain_id`, text `content`, `vector(768)` (configured dimension) `embedding`, JSON `langchain_metadata`. Use the documented PGVectorStore existing-table configuration and cosine distance. No approximate search index is needed for the PoC.
- `rag_index_config` has one singleton row recording embedding model and dimension. Create the extension, tables, and configuration together under a transaction and initialization lock; compare existing configuration before embedding. Querying must not silently create an empty index.
- Atomic writes use a separate SQLAlchemy connection against the same database/schema. In a transaction, acquire a source-specific advisory lock, delete that source's rows, and insert all precomputed replacements with bound parameters. Use supported pgvector binding or parameterized vector casts; do not manipulate integration internals or call delete/add methods that commit separately.
- Chunk IDs are UUID5 over canonical source path, content hash, splitting signature, and chunk ordinal. Metadata keys: `source`, `source_hash`, `split_signature`, `chunk_index`, `page` or `line_start`/`line_end`. PDF page numbers are one-based.

- [ ] Add runtime dependencies listed in Tech Stack (including `langchain-community` for PyPDFLoader and `langchain-text-splitters`) and pytest in the uv dev group. Resolve with `uv lock` on Python 3.14; report compatibility failures rather than silently changing the project floor.

### Task 2: Persistent PGVector Storage and Safe Replacement

**Files:** Modify `main.py`; create `compose.yaml`, `tests/test_storage.py`.

**Interfaces:**
- Consumes Task 1 configuration and documents.
- Produces `IndexStore(config: Config, embeddings: Embeddings)` with `initialize() -> None`, `check_compatible() -> None`, `replace_source(chunks: list[Document], vectors: list[list[float]]) -> None`, `search(question: str, k: int) -> list[Document]`, and `close() -> None`.
- `search` uses PGVectorStore; compatibility checks precede embedding requests. The adapter owns and releases its engines.

- [ ] Create Compose service and health check using the concrete defaults. Create a separate `rag_test` database for integration tests; never reset application tables in the regular `rag` database. Gate tests behind `RAG_TEST_DATABASE_URL` and skip with a clear reason when absent.
- [ ] Write storage tests using deterministic fake embeddings: insert/reopen/search persists source metadata; replacing many chunks with one removes old chunks; an invalid vector during replacement leaves old rows intact; unrelated files remain; model/dimension mismatch fails before fake embeddings are invoked; initialization repeats safely; empty and absent indexes give actionable errors. Assert rollback with an actual database insertion error inside the transaction.
- [ ] Run `docker compose up -d --wait` and create the test database, then run `uv run pytest tests/test_storage.py -q` with the test URL. Expected failures for absent storage interfaces; record environment blockers if Docker is unavailable.
- [ ] Implement initialization, compatibility checks, atomic replacement, and PGVectorStore search. Validate vector counts/dimensions and nonempty chunks before mutation. Use fixed SQL identifiers and bound source paths/metadata/vector values. A source lock serializes concurrent replacements. Close connections in error paths. Do not automatically drop or rebuild incompatible tables.
- [ ] Run the same storage tests; expected all pass against PostgreSQL, not an in-memory substitute. Run `docker compose config --quiet`; expected exit 0.
- [ ] Commit Task 2 files with `feat: persist and retrieve document chunks in pgvector`.
